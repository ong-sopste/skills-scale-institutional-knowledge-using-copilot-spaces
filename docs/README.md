# OctoAcme Project Management Documentation

## Overview

This directory contains the complete OctoAcme project management playbook—a collection of lightweight, iterative processes for running cross-functional projects. Our approach prioritizes customer value, clear ownership, and data-informed decision-making while encouraging team feedback and psychological safety.

OctoAcme's project management methodology applies to all cross-functional projects that deliver product features, services, or integrations. Whether you're starting a new initiative, planning delivery, managing execution, or capturing learnings, you'll find guidance and templates in these documents.

## Core Principles

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead
- **Data-informed**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

## Project Lifecycle Overview

OctoAcme projects follow a structured lifecycle with clear phases, roles, and decision gates:

1. **Initiation**: Validate the business need, align stakeholders, and define success criteria
2. **Planning**: Break work into shippable increments, identify risks and dependencies, and align timelines
3. **Execution**: Build, test, review, and iterate on features with daily standups and regular demos
4. **Release**: Deploy to production with verification and stakeholder communication
5. **Close & Retrospective**: Capture learnings and feed improvements back into processes

## Key Artifacts

- **Project Charter / One-pager**: Problem statement, objectives, success metrics, and stakeholders
- **Roadmap and Release Plan**: Timeline and milestones for delivery
- **Sprint/Iteration Backlog**: Prioritized work with acceptance criteria and estimates
- **Risk Register**: Active risks, mitigations, and owners
- **Retrospective Notes**: Learnings and action items for continuous improvement

## Core Roles

- **Project Manager (PM)**: Coordinates delivery, schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success
- **Developers**: Implement features, collaborate on design, and ensure code quality
- **QA/Testing**: Validates quality and acceptance criteria
- **Stakeholders**: Provide inputs, approvals, and support

## Getting Started

**New to OctoAcme?**
1. Start with the [Project Management Overview](octoacme-project-management-overview.md) to understand our core principles and roles
2. Review [Roles & Personas](octoacme-roles-and-personas.md) to see your role and responsibilities
3. Check the communication cadence section in the Overview to know when and how we sync

**Starting a new project?**
1. Follow the [Project Initiation Guide](octoacme-project-initiation.md) to validate the idea and get stakeholder alignment
2. Move to [Project Planning](octoacme-project-planning.md) once approved to create your backlog and release plan
3. Use the Planning document's checklist to ensure you're ready for execution

**In active delivery?**
1. Use [Execution & Tracking](octoacme-execution-and-tracking.md) to manage daily standups, PRs, and quality standards
2. Refer to [Risks & Communication](octoacme-risks-and-communication.md) for risk escalation and stakeholder updates
3. Document blockers and dependencies; escalate at weekly syncs if needed

**Ready to release?**
1. Review the [Release & Deployment Guide](octoacme-release-and-deployment.md) for pre-release requirements and deployment checklists
2. Prepare release notes and rollback plans
3. Execute deployment and post-deploy verifications

**Wrapping up?**
1. Schedule a [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md) session
2. Capture learnings and create action items for process improvements
3. Review and track action items in the next sprint or project

## Communication Cadence

- **Daily standups** (15 min): Focus on progress, blockers, and dependencies
- **Weekly PM + PdM sync**: Alignment on roadmap, risks, and priorities
- **Twice-weekly team standups**: Delivery team coordination (or as agreed)
- **Monthly stakeholder updates**: Status, progress, and flagged risks
- **Sprint/Release demos**: Show progress and gather feedback
- **Retrospectives**: After each sprint, release, or milestone

## How to Use These Docs

- **Keep Project Charters updated** in the project repository (typically in the README or a dedicated docs folder)
- **Add process-specific docs** to `.copilot/` if you want Copilot Spaces to use them as context for team guidance
- **Reference templates**: Use the templates provided in each document when creating artifacts (one-pagers, risk registers, etc.)
- **Escalate questions**: If process guidance is unclear or a scenario isn't covered, raise an issue or ask during weekly syncs
